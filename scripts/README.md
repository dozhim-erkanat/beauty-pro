# Скрипты импорта каталога

Разовые скрипты, которыми наполнялся каталог. Обычная работа с товарами идёт
через админку — сюда лезть нужно, только если товаров много и заводить их
руками долго.

## Что уже импортировано

| Скрипт | Бренд | Товаров | Источник |
| --- | --- | --- | --- |
| `import_cutrin_all.py` | Cutrin, 6 потребительских линий | 94 | cutrin.fi |
| `import_marmara_all.py` | Marmara Barber, 18 категорий | 197 | marmarabarber.com |
| `import_immortal.py` | Immortal, 12 категорий | 89 | immortalrussia.ru |
| `import_tech.py` | Andis, Valera, Dewal, MRD Pro, inCRED | 33 | 9 разных сайтов |
| `import_marmara.py` | первый заход по парфюмерии (10 позиций) | — | оставлен для истории |
| `import_cutrin.py` | первый заход по BIO+ (10 позиций) | — | оставлен для истории |

Линии Cutrin: AINOA (33), BIO+ (22), MUOTO (18), VIENO (16), ROUTA (4),
HOHDE (1). Профессиональные линии (AURORA, PROMISE) не импортированы: там
183 оттенка красок, которые правильнее заводить вариантами одного товара.

`prepare_cutrin.py` — нормализация названий (убирает «NEW», КАПС и двойные
пробелы, `ml` → `мл`) и словарь переводов описаний на русский. Запускается до
импорта и готовит `data/cutrin_consumer_lines.json`.

Описания переведены на русский вручную и лежат в `data/*.json` — там же
объёмы, штрихкоды и характеристики.

## Как запустить

Скрипты идемпотентные: повторный запуск обновит существующие товары по `slug`,
а не создаст дубли.

```bash
export ANON=$(grep NEXT_PUBLIC_SUPABASE_ANON_KEY .env.local | cut -d= -f2)
export ADMIN_EMAIL=почта-администратора
export ADMIN_PASSWORD=пароль

python3 scripts/import_cutrin_all.py
python3 scripts/import_marmara_all.py
python3 scripts/import_immortal.py
python3 scripts/import_tech.py
```

Скрипт логинится как администратор и работает через обычный REST API Supabase,
подчиняясь тем же политикам RLS, что и админка. Сервисный ключ не нужен.

## Картинки

В репозитории картинок нет — они уже лежат в Supabase Storage (бакет `media`,
папка `products/`). Поля `local` в `data/*.json` указывают на файлы, которые
скачивались во временную папку при первом импорте.

Если понадобится перезалить с нуля — скачайте картинки по адресам из колонки
`img` (Marmara) или по штрихкоду с сайта Cutrin, положите в `img/` рядом с
проектом и запустите скрипт.

## Цены

- **Cutrin** — цен нет: на сайте бренда это закрытый B2B-каталог. Все 94
  товара импортированы как «Цена по запросу», проставлять нужно вручную.
- **Marmara Barber** — все 197 цен пересчитаны из турецких лир по курсу
  `1 ₺ = 9.700723 ₸` на 15.08.2026, округление вверх до 10 ₸, без наценки.
  Курс задан константой `RATE` в начале `prepare_marmara.py`; чтобы обновить
  цены, поменяйте её и прогоните подготовку с импортом заново.
- **Техника** (Andis, Dewal, MRD Pro, inCRED) — из рублей по курсу
  `1 ₽ = 5.4832 ₸`, ножи Andis с украинского сайта — по `1 ₴ = 10.2424 ₸`,
  курсы на 25.08.2026. У четырёх фенов Valera цен нет: сайт-источник их не
  публикует, товары заведены как «Цена по запросу».
- **Immortal** — цены пересчитаны из рублей по курсу `1 ₽ = 5.4816 ₸` на
  22.08.2026, округление вверх до 10 ₸, без наценки. У шести товаров старая
  цена в источнике оказалась ниже текущей — такие «скидки» отброшены.

`prepare_marmara.py` переводит турецкие названия на русский по словарю
(178 слов исходного каталога) и раскладывает товары по категориям на основе
поля `product_type` из Shopify. Названия — машинный перевод по словарю,
вычитка человеком не помешает.

## Immortal: одинаковые названия у разных товаров

Сайт-источник на Tilda, каталог забирается одним запросом к `store.tildacdn.com`.
Там семь разных восков называются одинаково — «ВОСК ДЛЯ ВОЛОС», а линейка или
аромат упомянуты где-то внутри описания.

`prepare_immortal.py` тянет данные, `disambiguate_immortal.py` разводит тёзок:
для каждой группы одноимённых берёт из описания то, чего нет у соседей по
группе — так вытаскиваются «Капитан Блэк», Platinum Edition, Smokey Puff.
Что развести не удалось (совпадают фото, цена и почти весь текст), помечается
как «(вариант 2)» — такие позиции стоит проверить в админке вручную.

**Адрес товара обязан быть уникальным.** В первой версии из адреса срезался
числовой идентификатор Tilda, и 89 товаров схлопнулись в 69: одноимённые
затирали друг друга при загрузке. Сейчас при совпадении к адресу добавляется
хвост идентификатора.

Имена файлов картинок привязаны к идентификатору товара, а не к адресу, —
переименование товара не рвёт связь с фотографиями.

## Партия техники: девять сайтов сразу

Ссылки приходят от менеджеров списком в WhatsApp, каждая — со своего магазина.
Поэтому разбор двухслойный:

- `scrape_common.py` — универсальная часть: JSON-LD `Product`, затем og-теги,
  затем микроразметка. Покрывает больше половины сайтов без настройки.
- `scrape_tech_sites.py` — правила под конкретные магазины: где искать
  галерею, `<h1>` и таблицу характеристик.

Грабли, на которые уже наступили:

- **Не «улучшайте» адреса картинок.** Попытка получить оригинал вместо
  превью (убрать `.370x370`, заменить `preview` на `big`) даёт 404 на
  половине сайтов. Сначала пробуем исходный адрес, улучшенный — как запасной.
- **Проверяйте, что скачалась картинка.** Магазины отдают HTML-заглушку с
  кодом 200; по размеру файла её не отличить, нужна проверка сигнатуры файла.
- **Цену берите только из разметки.** На странице OpenCart рядом с товаром за
  25 000 ₽ лежат числа 2 600 и 4 000 из блоков рассрочки и аксессуаров.

Четыре ссылки забрать не удалось: `vitrinapro.com`, `beautyforsale.eu` и
`hairpro.md` закрыты защитой от ботов либо отдают пустую страницу без
JavaScript. Такие карточки заводятся руками через админку.

## Права на фотографии

Фото и тексты взяты с сайтов брендов и годятся для демонстрации. Перед
запуском для клиента нужно получить официальные материалы у бренда
(дистрибьюторам их выдают) или подготовить свои.
